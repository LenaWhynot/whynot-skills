# Рилс из съёмки процесса

Отбраковка здесь **97-99,6%**: из 76 минут материала в дело идут 17 секунд.
Вся ценность в ОТБОРЕ, не в резке.

Отбор двухслойный, и оба слоя обязательны:

1. **статистика сужает** — сплошной проход по кадрам отбрасывает тряску, паузы, руку
   поверх работы, оставляя 40–60 кандидатов;
2. **глаза выбирают** — кандидаты отсматриваются полосами кадров, и только потом
   попадают в раскладку.

⚠️ Пять версий, собранных слепым алгоритмом, были забракованы подряд. Шестая, где кадры
были ОТСМОТРЕНЫ, попала. Не пропускайте второй слой.

## Справочники — читать по ходу, а не сразу

Метод разложен по трём файлам, чтобы не тащить всё в разговор одним куском:

| Файл | Когда читать | Что внутри |
|---|---|---|
| [reference/otbor-kadrov.md](reference/otbor-kadrov.md) | ищете кандидатов | что считать по кадрам, пороги-перцентили, четыре признака брака сверх «движения руки», почему метрика «движение» берёт не то, дубли одного состояния, маркер в цвет поверхности, ложная «кожа» на тёплом рисунке, тряска: камера или содержимое |
| [reference/sborka-i-ritm.md](reference/sborka-i-ritm.md) | шоты отобраны | каркас ролика, ритм с принятого эталона, вес хронометража на финал, `rotation` в метаданных, кадрирование и зум, титры, фиксация итога, рецепт серии |
| [reference/bolshie-fayly.md](reference/bolshie-fayly.md) | исходники в облаке и весят десятки гигабайт | почему перемотка по HTTP врёт, докачка диапазонами, замок с PID, проверка кусков пробами |
| [reference/cut-format.md](reference/cut-format.md) | заполняете раскладку | поля `cut.json` |

**Минимум, который надо знать до чтения справочников:**

- пороги — **перцентили этого файла**, а не абсолютные числа: настроенные на одном
  сюжете, на другом отсекают почти всё;
- кандидата смотреть **полосой кадров**, а не одним кадром из середины;
- у каждого автора **свой шаблон брендинга** (титры, концовка, длительность) —
  слой монтажа общий, слой брендинга берётся с его же принятых роликов;
- **отбор дешевле починки**: дрожащий кусок не стабилизируют, его не берут.

## Что в комплекте

```
bin/contact-sheet.sh   контактные листы по всему исходнику
bin/strip.sh           полоса кадров одного куска
bin/assemble.sh        сборка ролика по раскладке
bin/stab.py            стабилизация (нужна редко, см. reference/otbor-kadrov.md)
bin/analyze/feat.py    признаки по прокси → feat_<исходник>.npz
bin/analyze/best.py    кандидаты по устойчивости + активности
bin/analyze/best2.py   то же для ТЁМНОГО исходника
bin/analyze/active.py  окна, где рука реально работает
bin/analyze/pick_active.py  живость при ограничении на тряску
bin/analyze/gap.py     кандидат, максимально не похожий на уже выбранные
bin/analyze/dup.py     проверка раскладки на повторы состояния
bin/analyze/strips.py  полосы кадров пачкой
```

**Рабочая папка** (её путь — в `WORKDIR`, иначе текущая):

```
proxy/<исходник>.mp4     прокси 360p, 10 fps — по нему считается и смотрится всё
feat_<исходник>.npz      признаки этого исходника
cut.json                 раскладка ролика: src · ss · d · zoom · kind
```

⚠️ **Python-скриптам нужен numpy**, он не входит в мастер настройки:
`python3 -m pip install --user numpy`. Проверить: `python3 -c "import numpy"`.
ffmpeg скрипты ищут сами — в `PATH`, затем в `~/.whynot-bin`, куда его кладёт
мастер первого запуска.

## Порядок работы

Ниже `$S` — папка навыка, чтобы строки не разъезжались:

```bash
S="${CLAUDE_PLUGIN_ROOT}/skills/video-reel-from-process"
command -v ffmpeg >/dev/null || bash "$S/bin/setup-ffmpeg.sh"
python3 -c "import numpy" 2>/dev/null || python3 -m pip install --user numpy
```

**1. Прокси на каждый исходник — один раз, дальше работаем только по нему.**

```bash
mkdir -p proxy
ffmpeg -nostdin -v error -i ИСХОДНИК.MP4 -vf "scale=-2:360,fps=10" -y proxy/A001.mp4
python3 "$S/bin/analyze/feat.py" proxy/A001.mp4 feat_A001.npz
```

**2. Посмотреть весь исходник глазами** — контактные листы по 24 кадра с подписью времени:

```bash
bash "$S/bin/contact-sheet.sh" proxy/A001.mp4 листы 72
```

**3. Кандидаты в шоты** — машина сужает, дальше решают глаза:

```bash
python3 "$S/bin/analyze/best.py"        feat_A001.npz 2 300 1.5 6   # устойчивые + живые
python3 "$S/bin/analyze/pick_active.py" feat_A001.npz 2 300 1.5 6   # живость при лимите на тряску
python3 "$S/bin/analyze/active.py"      A001 2 300 1.5 5            # где рука реально работает
python3 "$S/bin/analyze/gap.py"         A001 2 300 1.5 44.5 73.6    # непохожий на уже выбранные
```

**4. Каждого кандидата проверить ПОЛОСОЙ кадров**, а не одним кадром:

```bash
bash  "$S/bin/strip.sh" proxy/A001.mp4 44.5 1.5 полосы/01.png
python3 "$S/bin/analyze/strips.py" proxy/A001.mp4 "$PWD/полосы/all.png" 1.5 44.5 73.6 128.0
```

**5. Раскладка** — `cut.json` в рабочей папке; поля описаны в
[`reference/cut-format.md`](reference/cut-format.md), готовый образец — `reference/cut-format.json`.
Перед сборкой прогнать проверку на повторы состояния:

```bash
python3 "$S/bin/analyze/dup.py"
```

**6. Сборка и приёмка.** Собрать, затем снова посмотреть полосами — уже готовый ролик:

```bash
bash "$S/bin/assemble.sh" ИСХОДНИК.MP4 раскладка.txt рилс.mp4
bash "$S/bin/strip.sh" рилс.mp4 0 30 проверка.png
```
