# Рилс из съёмки процесса

Из часа съёмки в ролик попадает 20–30 секунд. Отбраковка почти стопроцентная,
и вся работа — это **отбор**, а не резка.

## Правило номер один: смотреть кадры глазами

**Нельзя выбирать моменты по одним цифрам.** Метрика не знает, красиво ли:
она честно находит места, где больше всего меняются пиксели, — а меняются они там,
где поехала камера или рука закрыла работу.

Порядок всегда двухслойный:

1. **Цифры сужают.** Сплошной проход по видео отбрасывает тряску, паузы и черноту —
   остаётся 30–50 кандидатов.
2. **Глаза выбирают.** Собрать контактные листы, посмотреть их и выбрать финальные 15–20
   с пониманием сюжета: что человек делает, в каком порядке, где видно продвижение.

## Порядок

### 0. Проверить ffmpeg

```bash
command -v ffmpeg || bash "${CLAUDE_PLUGIN_ROOT}/skills/first-run-setup/bin/setup-ffmpeg.sh"
```

### 1. Контактные листы по всей съёмке

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/video-reel-from-process/bin/contact-sheet.sh" съёмка.mp4 листы 60
```

Кладёт в `листы/` картинки по 24 кадра, каждый подписан временем. Час съёмки —
три-четыре листа. **Посмотреть их** и выписать, что происходит и когда: с чего начали,
что появилось в середине, чем закончили. Это карта сюжета, без неё ролик рассыпается.

### 2. Кандидаты — полосой, а не одним кадром

Выбрали кусок по контактному листу — **посмотрите, что внутри него**:

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/video-reel-from-process/bin/strip.sh" съёмка.mp4 512 1.4 полосы/01.png
```

Шесть кадров по всей длительности куска. Один кадр из середины врёт: в начале может
проноситься рука, сзади проходить человек, камера — дёргаться. На полосе это видно сразу.

⚠️ Не смотреть финальных кандидатов на мелких превью. Кадр уже 240 пикселей —
и «плечо в углу» окажется головой во весь экран.

### 3. Собрать раскладку

Сюжет важнее красоты отдельного кадра. Правила, которые держат ролик:

- **Показывать продвижение.** Куски идут по времени: было → становится → стало.
  Два куска, где работа выглядит одинаково, — это один кусок, второй убрать.
- **Каждый кусок 0,8–2 секунды.** Первый и последний можно длиннее: вход и итог.
- **Начинать с узнаваемого**, заканчивать результатом. Зритель должен за секунду
  понять, что происходит, и досмотреть ради «что получилось».
- 15–20 кусков на 25–35 секунд. Меньше — не складывается ритм, больше — рябит.

Раскладка — обычный текстовый файл, по строке на кусок: старт и длительность.

```
12.5 1.4
48.0 1.2
136.2 1.6
```

### 4. Сборка

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/video-reel-from-process/bin/assemble.sh" съёмка.mp4 раскладка.txt рилс.mp4
```

Режет по раскладке, приводит к вертикали 1080×1920 и склеивает. Кроп по умолчанию
по центру; работа не в центре кадра — пятым аргументом `left`, `right` или число.

### 5. Посмотреть готовое

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/video-reel-from-process/bin/strip.sh" рилс.mp4 0 30 проверка.png
```

Смотреть **на собранном ролике**, а не на кандидатах. Здесь видно то, чего не видно
по кускам: повторы, провал в середине, слишком длинный вход.

## Три ошибки, которые повторяются у всех

1. **Гнаться за максимумом движения.** Больше всего движения там, где рука закрывает
   работу. Такой ролик получается «про руку», а не про то, что человек делает.
2. **Брать куски подряд.** Соседние секунды почти одинаковы. Разносить по всей съёмке.
3. **Ставить два похожих куска.** Прежде чем добавить кусок в раскладку, сравнить его
   с предыдущим выбранным: похожи — второй не нужен, каким бы хорошим он ни был.

## Чего не делать

- Не публиковать самому **молча**. Ролик готов — предложи поставить его в очередь
  навыком `video-to-socials`; он спросит подтверждение перед постановкой.
- Не добавлять музыку без просьбы: у площадок свои правила, и чужой трек может стоить охвата.
- Не «улучшать» цвет и не крутить скорость, пока не спросили. Сначала показать честную сборку.
