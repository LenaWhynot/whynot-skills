# Ролики из записи с речью

Из часовой записи в дело идут 3–5 кусков по 30–60 секунд. **Вся ценность в отборе.**
Резать умеет любая программа; выбрать, что резать, — нет. Поэтому порядок такой:
сначала текст, потом смысл, и только потом ffmpeg.

## Правило номер один: резать по смыслу, а не по времени

Не делить запись на равные части и не брать «первые тридцать секунд». Годный кусок —
тот, где **мысль начинается и заканчивается внутри него**: вопрос → ответ → вывод.
Человек, который увидит ролик без контекста, должен всё понять.

Признаки, что кусок годится:

- начинается с утверждения или вопроса, а не с середины фразы и не с «ну вот»;
- заканчивается точкой, а не на вдохе;
- понятен без предыдущих сорока минут — внутри нет «как я говорил выше»;
- 30–60 секунд. Короче — не успевает быть полезным, длиннее — не досматривают.

## Порядок

### 0. Проверить окружение — до всего остального

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/video-clips-from-talk/bin/check-env.sh"
```

Скрипт говорит, что стоит, а чего нет. Нет `ffmpeg` — дальше идти бессмысленно,
дать человеку ровно одну команду под его систему:

| Система | Команда |
|---|---|
| macOS | `brew install ffmpeg` |
| Windows | `winget install Gyan.FFmpeg` |
| Linux | `sudo apt install ffmpeg` |

### 1. Спросить, каким путём распознавать речь

**Это единственный вопрос, который стоит задать человеку до работы.** Оба пути рабочие,
разница в цене и приватности — решать ему, а не вам:

| Путь | Что происходит | Честная цена |
|---|---|---|
| **Локально** | распознавание идёт на его компьютере, модель качается один раз | бесплатно и приватно, но первая установка 20–30 минут и ~1,5 ГБ |
| **Облако** | аудио уходит в сервис по его ключу | работает сразу, но платно по минутам и файл покидает компьютер |

Не выбирать за него молча. Спросить одной строкой и запомнить ответ в файле состояния,
чтобы в следующий раз не спрашивать.

Локальный путь ставится так (один раз, минут двадцать):

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/video-clips-from-talk/bin/setup-local-asr.sh"
```

### 2. Расшифровка со временем

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/video-clips-from-talk/bin/transcribe.py" запись.mp4
```

Рядом с видео появятся `запись.srt` (для субтитров) и `запись.txt` (для чтения).
Час записи распознаётся за 5–15 минут — на это время **не сидеть без дела**:
пока идёт, прочитать `запись.txt` по мере готовности или подготовить папку вывода.

⚠️ Не пересказывать запись по звуку и не выдумывать тайминги. Всё, что дальше, —
только из `.srt`, там реальное время каждой фразы.

### 3. Отбор — самый важный шаг

Прочитать расшифровку целиком и выписать кандидатов. На каждого:

- время начала и конца (из `.srt`, с точностью до секунды);
- о чём кусок одной строкой;
- почему взяли — что человек унесёт из этих сорока секунд.

**Показать список человеку до нарезки, если он просил участвовать.** Если он сказал
«делай сам до конца» — не спрашивать, но список всё равно составить: он пойдёт в опись.

Три ошибки отбора, которые видно сразу:

1. **Куски рядом.** Два клипа из одной минуты — это один клип. Разносить по записи.
2. **Обрезанное слово.** Начало по `.srt` — это начало *реплики*; сдвинуть старт
   на полсекунды назад, конец на полсекунды вперёд, иначе слышно «…дравствуйте».
3. **Кусок про контекст.** «Сейчас расскажу про три способа» — это анонс, а не мысль.
   Брать то, где содержание, а не оглавление.

### 4. Нарезка

По куску за раз:

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/video-clips-from-talk/bin/make-clip.sh" \
     запись.mp4 запись.srt 00:12:34 48 ролики/01.mp4
```

Аргументы: исходник · субтитры · старт · длительность в секундах · куда положить.
Скрипт сам обрежет кадр до вертикального 1080×1920 по центру и вошьёт крупные субтитры.

Лицо не по центру кадра — сдвинуть кроп пятым аргументом (`left`, `right` или число
пикселей от левого края):

```bash
... ролики/01.mp4 right
```

### 5. Опись

Рядом с роликами положить `ролики/опись.md`: номер · время в исходнике · о чём ·
первая фраза. Без неё через неделю никто не вспомнит, откуда какой ролик и что в нём.

## Проверить перед выдачей

Три вещи, каждая ловит свой класс брака:

```bash
# длительность каждого ролика — должно быть 30–60 с
for f in ролики/*.mp4; do
  printf '%s ' "$f"; ffprobe -v error -show_entries format=duration -of csv=p=0 "$f"
done
# размер кадра — должно быть 1080x1920
ffprobe -v error -select_streams v -show_entries stream=width,height -of csv=p=0 ролики/01.mp4
```

И **посмотреть первую и последнюю секунду каждого ролика глазами** — там живут
обрезанные слова, которых в цифрах не видно:

```bash
ffmpeg -nostdin -i ролики/01.mp4 -vf "select='lt(t,1)+gt(t,duration-1)',scale=240:-1,tile=6x1" \
       -frames:v 1 -y /tmp/edges01.png
```

## Чего не делать

- **Не публиковать самому молча.** Ролики готовы — предложи поставить их в очередь
  навыком `video-to-socials`; он спросит подтверждение перед постановкой.
- **Не заливать исходник в облако** без прямой просьбы. Если выбран облачный путь
  распознавания — сказать вслух, что аудио уходит туда, ещё до отправки.
- **Не выдумывать субтитры.** Текст только из `.srt`. Опечатку в терминах —
  поправить в `.srt` и перегнать, а не дописать от себя.
- **Не гнаться за количеством.** Пять хороших роликов лучше пятнадцати средних:
  канал живёт качеством, а не объёмом.
