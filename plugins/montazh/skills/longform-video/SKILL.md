# Длинное видео для YouTube

Половина работы здесь та же, что в коротком ролике: расшифровка, чистка речи, звук,
субтитры — те же скрипты из `reel-from-take/bin/`. **Но три вещи другие, и на них
ломаются все, кто просто «сделал рилс подольше».**

## Чем длинное отличается от короткого — по существу

| | короткий ролик | длинное видео |
|---|---|---|
| **паузы** | режем плотно, до 0,2–0,35 с | **оставляем дыхание.** Убираем только мусор: фальстарты, «эээ», повторы, оговорки. Плотно уплотнённая 15-минутная речь звучит как скороговорка и утомляет к пятой минуте |
| **задача монтажа** | выбрать ОДИН лучший кусок | **собрать структуру** из блоков: что сначала, что потом, что выбросить целиком |
| **удержание** | хук в первые 3 секунды | хук в первые 15–30 секунд **плюс** обещание структуры («разберём три вещи») — иначе уходят на второй минуте |
| кадр | 9:16 вертикаль | 16:9 горизонталь (1920×1080) |
| субтитры | вшиты в кадр | **отдельным файлом `.srt`** — YouTube показывает свои; вшивать только если делаете и вертикальную версию |
| графика | карточка на каждую фразу | крупные плашки на разделах, реже и спокойнее |
| рендер | один проход | **блоками, потом склейка** — 20 минут одним проходом легко упасть на середине |

## Порядок работы

```bash
S="${CLAUDE_PLUGIN_ROOT}/skills"
export ZAVOD_WORK="$PWD"
```

**1. Разбор материала — теми же скриптами, что для короткого.**

```bash
python3 "$S/reel-from-take/bin/prepare.py"      # дорожки + опись
python3 "$S/reel-from-take/bin/transcribe.py"   # расшифровка с таймкодами
python3 "$S/reel-from-take/bin/energy.py"       # карта речи: блоки и паузы
```

**2. Карта смысла — главное и только руками.**

Прочитать расшифровку и выписать **блоки**: о чём говорится, с какой по какую секунду,
в каком файле. Получается таблица на 8–20 строк:

```json
[
  {"src": "rec1", "in": 12.4,  "out": 95.2,  "тема": "почему это вообще проблема", "роль": "интро"},
  {"src": "rec1", "in": 210.0, "out": 480.5, "тема": "первый способ, с демонстрацией", "роль": "часть 1"},
  {"src": "rec2", "in": 30.1,  "out": 260.0, "тема": "второй способ", "роль": "часть 2"},
  {"src": "rec1", "in": 640.0, "out": 705.0, "тема": "что я бы делал иначе", "роль": "вывод"}
]
```

⚠️ **Порядок блоков в готовом видео не обязан совпадать с порядком записи.** Это
главное отличие от короткого ролика: там хронология — правило, здесь она — материал.
Часто сильный кусок сказан в конце записи, а по смыслу он открывает.

⚠️ **Целые блоки выбрасывать нормально и нужно.** Если тема провисает или повторяет
предыдущую — выкинуть весь блок. Но это **решение человека, а не монтажа**: спросить
прямо, назвав блок его словами и сказав, сколько минут это сэкономит.

**3. Чистка внутри блоков — мягче, чем в коротком.**

```bash
python3 -c "import sys; sys.path.insert(0,'$S/reel-from-take/bin'); from densify import densify; \
            print(densify('rec1', [[12.4,95.2]], thr_off=14, ignore_gaze=True))"
```

`thr_off` для длинного брать **мягче** (14–17 вместо 22): пусть остаются короткие
паузы между фразами. Что убираем всегда: фальстарты, «эээ» и «ну», повтор одного слова,
оборванные заходы, кашель и щелчки.

**4. Сборка блоками, потом склейка.**

```bash
# каждый блок — своим проходом, 16:9
ffmpeg -nostdin -v error -i raw/rec1.mp4 -ss 12.4 -to 95.2 \
  -vf "scale=1920:1080:force_original_aspect_ratio=increase,crop=1920:1080,fps=30,setsar=1" \
  -c:v libx264 -preset medium -crf 20 -pix_fmt yuv420p \
  -af "highpass=f=85,afftdn=nf=-25,equalizer=f=200:t=q:w=1:g=-2.5,equalizer=f=3500:t=q:w=1:g=3,highshelf=f=8500:g=3,loudnorm=I=-14:TP=-1.5" \
  -y blocks/01.mp4

# склейка встык
: > list.txt; for f in blocks/*.mp4; do echo "file '$PWD/$f'" >> list.txt; done
ffmpeg -nostdin -v error -f concat -safe 0 -i list.txt -c copy -y video.mp4
```

Звуковая цепочка та же, что в коротком, включая `loudnorm=I=-14` и **без компрессора**.
Подробности и замеры — [reel-from-take/reference/zvuk.md](../reel-from-take/reference/zvuk.md).

**5. Главы с таймкодами.** YouTube делает главы сам, если в описании есть список,
который начинается с `00:00`, а глав не меньше трёх и каждая не короче 10 секунд:

```
00:00 О чём это видео
01:35 Почему обычный способ не работает
05:12 Первый способ, с демонстрацией
11:40 Второй способ
17:05 Что я бы сделал иначе
```

Считать таймкоды **по готовому файлу**, а не по плану: после чистки длительности блоков
уехали. Пересобрал видео — пересчитай главы, иначе они врут.

**6. Субтитры отдельным файлом.**

```bash
python3 "$S/longform-video/bin/srt.py" tc/rec1.json subs.srt
#   третий аргумент — сдвиг в секундах, если блок в готовом видео стоит не там,
#   где был в записи: python3 srt.py tc/rec2.json part2.srt 312.4
```

Строки собираются до 42 знаков и не дольше 3,5 с, разрыв на паузе больше 0,7 с.
`.srt` загружается в YouTube рядом с видео. Вшивать в кадр не надо: зритель включает
их сам, а вшитые мешают, если он смотрит с телевизора.

## Интро: первые 30 секунд

- **Сначала проблема или результат, потом приветствие.** «Привет, меня зовут…» в первой
  секунде — главная причина уходов.
- **Обещание структуры** одной фразой: «разберём три способа, третий — тот, что работает».
- **Показать результат заранее**, если он визуальный: смонтированный кадр, готовый экран,
  цифру.
- Не вставлять брендовую заставку в начало. Она уместна после хука, если вообще нужна.

## Графика в длинном

Спокойнее и крупнее, чем в коротком:

- **плашка с названием главы** на её первой секунде — этого уже достаточно;
- вставки и скриншоты — через `broll-library`, правила те же, но реже: раз в 30–60 секунд,
  а не на каждую фразу;
- полноэкранный скриншот вместо карточки, когда речь о деталях интерфейса: в 16:9
  места хватает, и человеку не надо щуриться.

## Гейт перед выгрузкой

- первые 30 секунд отвечают на «зачем мне это смотреть»;
- нет блока, который повторяет предыдущий;
- главы посчитаны по готовому файлу и первая — `00:00`;
- звук ровный по всей длине (проверить громкость в начале, середине и конце — блоки
  писались в разное время);
- `.srt` сверен с речью в трёх случайных местах;
- длительность названа вслух: если получилось 25 минут из 40 — сказать, что выбросили.

## Границы

- Навык не решает за человека, какой блок выбросить: предлагает, но спрашивает.
- Не режет паузы плотно — это осознанно, см. таблицу выше.
- Не делает из длинного короткие: для этого `video-clips-from-talk`, и запускать его
  надо **после** того, как длинное принято.
